# image-watermark

Cloudflare Worker for `image.limooo.cn/*`: the **A2 normalising proxy** that maps a
"logical path" back to a public static asset and always returns the watermarked or
the clean variant.

## Background (A2)

The full-size portfolio originals (`src/static/portfolio/*`) are **no longer
published**. The public Pages bundle contains:

- `/static/wm/portfolio/*`: watermarked full images (pre-generated by `src/build.py`
  with Pillow).
- `/static/portfolio/thumbs/*`: clean thumbnails (used only by the home-page cards).
- `/static/qr-codes/*`, `/static/icons/*`: clean assets.
- The original `/static/portfolio/<image>` was removed from the bundle and returns 404.

The Worker therefore **no longer distinguishes originals from watermarks by
Referer** (originals do not exist at any public address), so there is no forged
Referer to bypass.

## Behaviour

- `/portfolio/<image>.webp|jpg|jpeg|png` at the portfolio root -> **always** returns
  the watermarked variant `/static/wm/portfolio/<image>`, whatever the source.
- `/portfolio/thumbs/<image>.webp|avif` -> returns the generated clean thumbnail at
  `/static/<path>`. Nested portfolio paths and other portfolio formats return 404.
- `/qr-codes/*`, `/icons/*`, and other non-portfolio image paths -> returns the clean
  static asset at `/static/<path>`.
- Accepts the `images.limooo.cn` style `/static/portfolio/...` too: the `/static`
  prefix is stripped before normalisation.
- The roots of `images.limooo.cn` and `image.limooo.cn` redirect to `https://limooo.cn/`;
  `images.limooo.cn` remains the static asset host.
- Never proxies `/api/*`; anything that is not an image or an allowed static directory -> 404.
- Accepts only `GET` and `HEAD`; other methods return 405 without contacting the origin.
- A missing watermark variant returns 404 and **never falls back to the original**
  (so an old cached clean image cannot be mistaken for an origin response).

## Architecture

Watermark variants are not composited inside the Worker (Workers Free allows 10 ms
CPU per request and has no runtime Canvas / image re-encoding API; Image Resizing is
a paid feature). `src/build.py` generates them into `public/static/wm/portfolio/`
with Pillow and they ship with Cloudflare Pages. The Worker only normalises paths
and proxies, so its CPU cost is near zero.

Only `portfolio/` (portfolio photos) is watermarked: `qr-codes/` (a watermark would
break scanning) and `icons/` (brand logo/favicon) are not.

## Caching

- Browser / edge: `Cache-Control: public, max-age=86400, s-maxage=86400`. Under A2
  the same URL returns the same bytes for every source, so there is **no
  `Vary: Referer`**.
- Worker side: cached in the Cache API per origin URL (watermarked and clean are
  different URLs), so they never contaminate each other and the origin is fetched at
  most once a day.

## Deploy

```sh
# 1) rebuild and deploy Pages (regenerates public/static/wm/ and drops the originals)
bash ops/pages_deploy.sh

# 2) deploy the Worker (updates the image.limooo.cn routing logic)
bash ops/workers_deploy.sh --worker=image-watermark
```

`ops/workers_deploy.sh` runs
`wrangler deploy --config ops/image-watermark/wrangler.toml`; credentials come from
the local `secrets/webauthn.env` (the same file the Pages deploy reads) and are
never written to the repository.

## Route and DNS

`image.limooo.cn/*` -> `image-watermark`, with `image.limooo.cn` CNAME'd to
`limooo.pages.dev` (proxied).

**The route is not declared in `wrangler.toml` on purpose.** Custom domains and
their routes are managed in the Cloudflare Dashboard (Workers & Pages ->
image-watermark -> Settings -> Domains & Routes); `ops/cloudflare/README.md` is the
inventory of what is Dashboard-only. Adding a `routes` block would let every deploy
rewrite the live route set, which this repository cannot diff or roll back.

## Publishing a watermark appearance change

`src/build.py` composites `src/static/icons/Limooo-xtext.svg` directly onto each
portfolio image. The SVG's own opacity is preserved and no backing plate is added.
After changing the SVG or composite placement/size:

1. `bash ops/pages_deploy.sh` (regenerate and deploy the variants)
2. bump `WM_VERSION` in `src/index.js` (to bypass the old CDN cache), then
   `bash ops/workers_deploy.sh --worker=image-watermark`

## Original-image backup

Originals exist only in the local `src/static/portfolio/` and in the private R2
bucket `limooo-originals`. Back up with `bash ops/upload_originals.sh` (it creates
the private bucket on first run).
